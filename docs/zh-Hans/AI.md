# AI 策略系统

## 架构概览

AI 系统由三个组件构成，分工明确：

```
┌─────────────────────────────────────────────────────────────────┐
│                    Flutter UI 层                                 │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  _processAiTurn()                                        │  │
│  │  1. 调用 process_ai_turn (Rust 执行 roll → end_turn)      │  │
│  │  2. 播放骰子 & 移动动画                                    │  │
│  │  3. 调用 ai_evaluate (buy) → 执行购买                      │  │
│  │  4. 调用 ai_evaluate (upgrade_target) → 执行升级           │  │
│  │  5. 如果下一个也是AI，递归调用                              │  │
│  └───────────────────────────────────────────────────────────┘  │
│                                                                  │
│  Rust FFI Bridge (core:command:)                                 │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  process_ai_turn   → TurnProcessor (roll + end_turn)      │  │
│  │  ai_evaluate (buy) → StrategicAiDecisionMaker::evaluate_buy│  │
│  │  ai_evaluate (upgrade) → best_upgrade_target              │  │
│  └───────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                    Rust 引擎层                                    │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  TurnProcessor.process_turn_with_bus()                    │  │
│  │  - 执行 roll 命令（骰子 + 移动 + 地块事件）                │  │
│  │  - 执行 end_turn 命令                                     │  │
│  │  - 不处理 buying（交由 Flutter 在动画后处理）              │  │
│  └───────────────────────────────────────────────────────────┘  │
│                                                                  │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  AiSubscriber (EventBus 订阅者)                            │  │
│  │  - 监听 card_shop_landed → 策略性购买卡片                  │  │
│  │  - 监听 lottery_landed → 有节制地购买彩票                  │  │
│  │  - 监听 player_sent_to_jail → 分阶段处理保释/留监          │  │
│  └───────────────────────────────────────────────────────────┘  │
│                                                                  │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  StrategicAiDecisionMaker (决策引擎)                       │  │
│  │  - evaluate_buy()      — 是否购买地产                      │  │
│  │  - score_property()    — 地产评分 (0-300+)                │  │
│  │  - best_upgrade_target() — 最佳升级目标                   │  │
│  │  - required_safety_reserve() — 安全储备金计算              │  │
│  └───────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────┘
```

## 1. StrategicAiDecisionMaker — 核心策略引擎

**文件位置：** [`crates/application/src/turn_processor.rs`](crates/application/src/turn_processor.rs)

### 1.1 地产评分系统 `score_property()`

为每块地产计算 0-300+ 的分数，分数越高越值得购买。

#### 评分维度

| 维度 | 权重范围 | 说明 |
|------|---------|------|
| 色组完成奖励 | 0 ~ +100 | 购买后完成色组 → 最高分 |
| 投资回报率(ROI) | 0 ~ +60 | L3租金 / 总升级成本 × 10 |
| 价格评分 | +5 ~ +30 | 便宜的地产得分更高 |
| 位置评分 | +5 ~ +25 | 基于距离监狱的格数（骰子概率） |
| 铁路溢价 | +10 ~ +70 | 收集全部4条铁路的动机 |
| 公用事业溢价 | +15 ~ +25 | 收集全部2个公用事业的动机 |
| 可负担性惩罚 | -50 ~ 0 | 现金紧张时降低分数 |

#### 色组完成奖励逻辑

```rust
if missing_for_monopoly == 1 {
    // 购买后立即完成色组 → 最高优先级
    score += match group_size {
        2 => 80,   // 2地产组：极易完成
        3 => 100,  // 3地产组：高价值
        _ => 60,
    };
} else if owned_in_group >= 1 {
    // 已拥有组内部分地产
    score += match group_size {
        2 => 40,   // 差一个完成
        3 => 60,   // 差两个完成
        _ => 20,
    };
}
```

#### 位置评分逻辑（基于骰子概率）

从监狱(Jail)出发的骰子概率分布：
| 距离监狱格数 | 落地概率 | 分数 |
|-------------|---------|------|
| 7 | 16.7% | 25 |
| 6 或 8 | 13.9% | 22 |
| 5 或 9 | 11.1% | 18 |
| 4 或 10 | 8.3% | 14 |
| 3 或 11 | 5.6% | 10 |
| 2 或 12 | 2.8% | 6 |

**经典地图中橙色组（prop_9/prop_10/prop_11）在监狱后6-9格，累计落地概率高达 38.9%！**

### 1.2 战略性购买评估 `evaluate_buy()`

#### 决策规则（按优先级排列）

1. **规则1 — 完成色组**：如果购买此地产将完成一个色组，且现金足够 → **必定购买**
2. **规则2 — 接近色组完成**：如果已拥有组内50%+的地产，且剩余现金足够购买组内所有未拥有的地产 → **强烈购买**
3. **规则3 — 差一个完成色组**：已拥有组内2/3的地产 → **强烈购买**
4. **规则4 — 铁路**：现金 ≥ 价格 + 200 → **积极购买**
5. **规则5 — 公用事业**：已拥有一个或只有一个公用事业 → **适度购买**
6. **规则6 — 分数门槛**：基于动态阈值的分数决策：
   - 现金 > $1000（前期）：门槛 40
   - 现金 $500~$1000（中期）：门槛 55
   - 现金 < $500（后期）：门槛 70
7. **规则7 — 安全限制**：单次消费不超过现金的50%

### 1.3 战略性升级评估 `best_upgrade_target()`

#### 前置条件

- 只考虑已拥有**完整色组**的地产
- 升级等级不能超过 `max_upgrade_level`
- 必须能负担升级费用 + 安全储备金

#### 优先级评分

```rust
priority = ROI * 50
         + (if 是组内最低等级则 +30)     // 均衡建设奖励
         + (if 首次升级则 +20)           // 首级升级影响最大
         - 当前等级 * 5                  // 高级递减惩罚
```

**均衡建设策略**：只升级色组中等级最低的地产，确保组内所有地产等级一致，最大化整体租金收入。

### 1.4 安全储备金计算 `required_safety_reserve()`

**核心原则：** "如果我连续3次踩到对手最强的地，会不会破产？"

```
安全储备金 = MAX(
    对手最高租金 × 3 + 200,    // 能扛3次最坏情况
    100                          // 最低保障
)
```

**对手最高租金**的计算：
1. 遍历所有被**对手玩家**拥有的地产
2. 计算每块地产的 `current_rent()`（如果启用了 `group_rent_enabled` 且地产有 `linked_targets`，则计算连带租金总和）
3. 取最大值

**示例：**
| 场景 | 对手最强租金 | 安全储备金 |
|------|-------------|-----------|
| 对手拥有橙色组满级 ($72+$72+$80=$224) | $224 | $224×3+200 = **$872** |
| 对手只有一块低级地 ($10) | $10 | $10×3+200 = **$230** |
| 没有对手有地产 | $0 | **$100** |

## 2. AiSubscriber — 响应式事件决策

**文件位置：** [`crates/application/src/ai_subscriber.rs`](crates/application/src/ai_subscriber.rs)

AiSubscriber 通过 EventBus 监听特定事件，在事件发生时立即做出决策。

### 2.1 卡片商店决策 `handle_card_shop_landed()`

#### 卡片评分系统

| 卡片 | 价格 | 评分条件 | 分数 |
|------|------|---------|------|
| get_out_of_jail | $150 | 现金充足 | 100 |
| | | 现金紧张 | 30 |
| double_rent | $200 | 拥有≥2个地产 | 80 + 拥有数×5 |
| | | 拥有<2个地产 | 20 |
| bonus_200 | $100 | 现金 < $300 | 70 |
| | | 现金 $300~$500 | 50 |
| | | 现金 > $500 | 10 |

**策略：** 选择可负担且分数最高的卡片。

### 2.2 彩票决策 `handle_lottery_landed()`

- 仅当现金 ≥ 票价 + **$500** 时购买（视为可支配收入）
- 低现金时不参与彩票（避免影响流动性）

### 2.3 监狱决策 `handle_sent_to_jail()`

#### 分阶段策略

| 阶段 | 条件 | 行为 |
|------|------|------|
| 有免罪卡 + 后期 | 拥有≥3个地产且有 get_out_of_jail 卡 | 使用卡片出狱 |
| 前期 | 拥有≤2个地产 或 现金>$1500 | 支付保释金（继续收购） |
| 后期 | 拥有≥3个地产 | 留在监狱（避开对手高租地） |
| 无法负担 | 现金 < 保释金 | 留在监狱 |

**保释金计算：** `jail_turns × $50/回合`

## 3. 桥接命令 (`core:command:ai_evaluate`)

**文件位置：** [`crates/application/src/bridge.rs`](crates/application/src/bridge.rs)

### 3.1 请求格式

```json
{
  "command_type": "core:command:ai_evaluate",
  "source": "core",
  "payload": {
    "action": "buy | upgrade_target | score",
    "tile_id": "prop_1",        // buy/score 时需要
    "player_id": "player_0"     // 可选，默认用 active_player
  },
  "state": { /* 完整 GameState */ }
}
```

### 3.2 响应格式

**buy 动作：**
```json
{
  "action": "buy",
  "decision": "buy | pass",
  "score": 75,
  "tile_id": "prop_1"
}
```

**upgrade_target 动作：**
```json
{
  "action": "upgrade",
  "target": "prop_1 | null",
  "score": 85
}
```

**score 动作：**
```json
{
  "action": "score",
  "tile_id": "prop_1",
  "score": 75
}
```

## 4. Flutter 端执行流程

**文件位置：** [`flutter/lib/main.dart`](flutter/lib/main.dart) `_processAiTurn()`

```
_processAiTurn()
  │
  ├─ 1. 调用 core:command:process_ai_turn (Rust: roll→end_turn)
  │
  ├─ 2. 播放骰子动画 (8帧随机 → 显示真实值)
  │
  ├─ 3. 播放棋子移动动画 (每格150ms)
  │
  ├─ 4. 执行延迟UI动作 (对话框等)
  │
  ├─ 5. 评估购买: ai_evaluate(action: 'buy', tileId: pos)
  │     ├─ decision == "buy" → 执行 buy_property 命令
  │     └─ decision == "pass" → 记录跳过日志
  │
  ├─ 6. 评估升级: ai_evaluate(action: 'upgrade_target')
  │     ├─ target != null → 执行 upgrade_property 命令
  │     └─ target == null → 跳过
  │
  └─ 7. 如果下一个玩家也是AI → 递归调用 _processAiTurn()
```

## 5. 经济模型参考

### 租金公式

```
rent = base_price × (1 + level) / 10
```

| 等级 | 租金比例 | 示例($100地产) | 示例($400地产) |
|------|---------|---------------|---------------|
| 0 | 10% | $10 | $40 |
| 1 | 20% | $20 | $80 |
| 2 | 30% | $30 | $120 |
| 3 | 40% | $40 | $160 |

### 升级费用公式

```
cost = base_price × (1 + level) / 3
```

| 升级 | 费用比例 | 示例($100地产) |
|------|---------|---------------|
| 0→1 | 33% | $33 |
| 1→2 | 67% | $67 |
| 2→3 | 100% | $100 |

## 6. 后续开发建议

### 6.1 高级策略

- **抵押融资**：在需要购买关键地产时，自动抵押低价值地产
- **拍卖策略**：参与拍卖时的出价策略
- **交易策略**：与其他玩家交易的估价与谈判
- **股票市场**：如果启用了股票市场，纳入投资组合考虑

### 6.2 机器学习

- 使用 [`crates/infra/src/ai.rs`](crates/infra/src/ai.rs) 中的 `MonteCarloAgent` 作为基准
- 可考虑规则AI + MCTS 混合策略

### 6.3 配置化

- 将策略参数（分数权重、门槛值等）移到配置文件中
- 支持不同难度等级的预设配置

### 6.4 LLM 集成

- [`crates/infra/src/llm.rs`](crates/infra/src/llm.rs) 中的 `ConfigurableLlmClient` 支持规则覆盖
- 可通过 LLM 提示词实现"专家建议"模式，AI 先按规则决策，再让 LLM 提供修正建议
